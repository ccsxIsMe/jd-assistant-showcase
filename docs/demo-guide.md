# 软件工程师：可重复展示指南

入口 `/examples`，当前案例为“星桥问题追踪系统 · 软件工程师研究”，fixture `software-engineer@1`。**示例项目｜虚构材料｜预置分析结果**，不调用收费模型。资料、引用校验、草稿存储、快照、导入、局部审阅和撤销使用正式业务流程。

## 故事与文件

小团队需要问题表单、列表、状态流转、权限校验、条件查询及CSV导出。本案例资料明确选择React/TypeScript界面和Node.js/TypeScript接口，关系数据库的品牌、预算及工期仍未知。两份说明对**同一首版**的状态修改权限互相冲突：仅管理员、所有已登录成员。需要人决定，不能合并成已确认事实。

候选方向：现有服务组合（暂不新增招聘）、软件工程师（Web应用方向）、前后端分工。主要岗位能力包括React/TypeScript界面交付、Node.js接口与权限、SQL建模与查询、自动化测试/持续交付、Git协作与交付说明；不是对所有岗位套用同一要求。

`public/demo/software-engineer/` 内有可打开的 `reference.html`、`interface.png`、`software-brief.docx`、`software-resume.docx`、`resume.txt` 和资源清单。DOCX通过Mammoth实际提取验证，PNG标注坐标来自实际页面元素测量，网页为本地模拟来源。运行 `pnpm prepare:demo` 重建新旧两套文件，需要当前已安装Edge，不调用模型。

## 五至八分钟展示主线

1. 首页“体验完整示例”进入案例中心，在“AI帮我规划”选择“从头体验”。检查资料和模式标识，点击开始AI规划。
2. 展开关键证据，查看权限冲突和三种不同方案。可以选择“我不确定”或填写自定义回答，不会自动确认事实。
3. 选择软件工程师方案，查看逐条具体能力；处理权限问题或明确以假设继续，确认方案生成资料包。保存快照，在导入预览取消一条要求，确认部分导入。
4. 在工作台逐条确认任务与要求，主动生成JD。选中段落提出精简，预览差异后应用、拒绝或撤销；预置局部建议仅覆盖精简，不冒充任意指令分析。
5. “用当前岗位核对简历”：上传虚构简历DOCX，审阅隐私范围后主动确认。查看明确描述、描述不足、未体现、同一项目时间不一致四种状态；引用可定位原文。
6. 记录人工修正、重新核对并下载Markdown。报告保留模式、岗位标准、材料版本、来源快照与待核实问题，不作录用决定。

## 独立入口和重复操作

六张卡分别进入AI规划、共同研究、完整证据板、岗位JD、简历核对、研究历史，均有“查看完成版”和“从头体验”。每种种子保留当前实例，重复进入继续编辑。完成版预置确认和选择记入活动记录，不等于当前操作者审批。从头版草稿未分析，保留演示历史版本；导入的新岗位内容仍默认待确认。

主动研究演示：修改功能 → 切换AI规划检查修改 → 完整证据板查看冲突双方依据 → 删除关系并撤销 → 移动节点、调整标注 → 新快照 → 旧快照只读 → 返回草稿。两种研究模式共享业务数据，教程只改变视图，不修改确认状态。

## 安全重置与个人数据

案例中心明确确认重置，仅创建指定种子的新实例，旧实例归档，旧快照和资料保留。个人项目、其他导入工作区和个人副本不删除。复制完成版重新绑定项目、节点、引用、快照、岗位和简历ID，附件另存，保留虚构来源说明。

旧纸舟fixture `paperboat@1`、资料与快照仍兼容；新入口使用独立 `software-engineer:1:*` 指针，不清空用户数据。旧脚本见 [纸舟v1归档](demo-guide-paperboat-v1.md)。

超出预置覆盖范围时明确失败并保留输入。任意新岗位可手动整理，或配置本机真实AI后主动切换。真实失败不回退预置。切换模式不调用模型，真实分析前仍需审阅外部发送范围。无音频转写、自动联网看视频、扫描件OCR或自动网页截图。

数据按浏览器、域名和端口隔离，固定使用同一地址；清除站点数据会丢失本机内容，请定期导出研究资料和岗位备份。测试使用临时Edge上下文，不读取个人浏览器资料。
