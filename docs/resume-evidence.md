# 简历证据核对：价值、数据与边界

`/match`保留，但成为岗位共创的下游。工作区“用当前岗位核对简历”携带workspaceId，冻结岗位要求、来源修订、关联研究快照及当前JD。可以主动改用已保存版本；岗位变化仅提示更新，旧报告不重写。已有JD用户可以直接粘贴或导入JD，不必先建立研究。原文按行形成候选核对项，明确标为程序整理，允许编辑；不包装成AI提炼。

四种状态分别是有明确描述、描述不足、未找到描述、材料存在不一致。可定位不证明能力真实；未体现不代表不会。判断不使用性别、年龄等无关属性，不打录用分数、不排名、不自动决定录用淘汰。原评分API及历史序列化继续兼容，新主界面没有并行的评分表单。改造前匹配报告仅在页面内存，无历史持久报告可迁移。

`src/lib/resume/model.ts`定义Standard、ResumeMaterial、ResumeReport、Correction和ReviewSession。报告冻结标准及材料，人工修正单独保存，匹配同一标准和职业材料签名后可延续到重分析；撤销只处理对应修正。修改原文会形成新材料版本，不将旧引用绘制到新材料上。每条结果必须对应真实requirementId，quote必须在真实paragraphId中唯一出现；不一致必须有两个独立段落。位置校验不代替语义核查。

PDF.js/Mammoth在浏览器解析；不上传原文件，10MB、30000字、PDF最多50页。失败保留原文字，扫描件无OCR，旧.doc不支持。常见姓名、联系方式及无关个人属性行在发送前用等长空格遮盖；并非完整匿名化，用户需在预览中审阅。原始已解析文本仍存本机，页面明确告知，可删除本次记录或导出报告。

页面调用 `/api/resume/review` → `ai/resume-service.ts` → 共用DeepSeek适配层。密钥仅服务端读取，输入、输出、引用和迟到响应都校验；60/65秒超时，可取消，最多一次受控修复。示例固定返回覆盖范围明确的材料判断，改写案例材料超出范围会报错，不套用旧答案。真实失败无预置回退。

新报告保存在同一IndexedDB v3的resume-reviews中。列表只保留摘要，不一次预加载所有简历正文。删除先停止待保存任务，避免卸载时把已删除记录重新写入。保存失败保留内存编辑，可重试或导出。没有云同步、候选人库、跨设备恢复和外网背景检索。

本轮未运行真实收费模型；身份字段不变性只验证确定性预处理与示例逻辑，不宣称真实模型已达到相同稳定性。
